# R02 — методология: поиск, выгрузка и анализ мамских пабликов ВКонтакте и Telegram

Версия 1, 2026-11-08. Статус: **проект, сбор не начат**. Скрипты в `scripts/publics/`: классификатор проверен на тестовом примере, сборщики **написаны, но не проверены на живом API** (нет ключей).

## Что здесь факт, что замер, что допущение

- `ФАКТ`: пока ничего. Это методика, данных по ней ещё нет.
- `ЗАМЕР`: всё, что она даёт. Это З20 (размер и вовлечённость пабликов) и З21 (цена подписчика). Кроме того, проверка допущения Д14.
- `ДОПУЩЕНИЕ`: пороги решений в разделе 6. Они записаны **до** сбора, менять их после сбора нельзя.

## 2. Две выборки

| выборка | что в неё входит | зачем |
|---|---|---|
| **А. Местные** | сообщества и каналы для мам и беременных в НСО: город, районы, Бердск, Академгородок, Кольцово, Обь, Искитим | канал раздачи и партнёрства (П1, П3) |

## 3. Поиск (discovery)

### 3.1 Ключевые слова

Местные (выборка А):

```
мамы новосибирск, мамочки новосибирска, мамы нск, молодые мамы новосибирск, беременные новосибирск, декрет новосибирск, родители новосибирск, дети новосибирск, мамы академгородка, мамы бердска, мамы кольцово, мамы оби, мамы искитима, мамы левого берега, мамы заельцовского, мамы калининского, мамы кировского, мамы ленинского, мамы октябрьского, мамы первомайского, мамы советского, мамы центрального, мамы дзержинского, мамы железнодорожного, гв новосибирск, грудное вскармливание новосибирск, педиатр новосибирск
```

Федеральные экспертные (выборка Б):

```
педиатр, детский врач, грудное вскармливание, консультант по гв, прикорм, детский сон, атопический дерматит дети, детский аллерголог, неонатолог, здоровье ребёнка
```

### 3.2 ВКонтакте

1. **API (основной путь):** метод `groups.search` с параметром `q` по каждому слову. Для выборки А поиск делается дважды: с фильтром по городу и без него. Многие местные группы город в настройках не указывают. Код города Новосибирска берётся из `database.getCities` (q=«Новосибирск»), а не из памяти. По найденным id вызывается `groups.getById` с полями `members_count, activity, city, description, verified`.
2. **Без кода:** поиск сообществ в ВК по тем же словам, первые 30 результатов по каждому. Строки заносятся в `zamery/z20-publics-template.csv`.
3. **Снежный ком:** в каждом включённом паблике смотрим блок «Ссылки» и упоминания других пабликов в последних 30 постах. Новые паблики проходят тот же фильтр.

### 3.3 Telegram

1. **TGStat (tgstat.ru), без кода:** поиск каналов по тем же словам, категория «Семья и дети». Сохраняем подписчиков, средний охват поста и ERR, их TGStat показывает бесплатно.
2. **Telegram API (Telethon):** `contacts.SearchRequest` по словам отдаёт публичные каналы и группы. Число подписчиков даёт `GetFullChannelRequest`.
3. **Снежный ком:** пересылки и упоминания `@канал` в последних 100 постах включённых каналов.
4. **Группы-чаты** (`megagroup`) записываем только с названием и числом участников. Сообщения в них пишут люди, а не администратор. Это персональные данные, их не читаем и не выгружаем.

### 3.4 Фильтр включения (одинаковый для ВК и Telegram)

| шаг | правило |
|---|---|
| 1. дедупликация | один паблик на id или username |
| 2. аудитория | по названию, описанию и 10 последним постам: мамы или беременные, дети до 3 лет — да или нет |
| 3. география | А: НСО. Б: федеральный экспертный. Остальное исключить |
| 4. живой | ≥4 поста за последние 30 дней |
| 5. размер | ВК ≥1 000 участников, Telegram ≥500 подписчиков |
| 6. тип | `магазин`, `барахолка`, `клиника` — в отдельный список, в анализ аудитории не входят |

На каждом шаге записываем, сколько пабликов осталось. Воронка «найдено → после дедупликации → релевантные → живые → включены» идёт в отчёт, чтобы выборку можно было повторить.

Разметку шагов 2, 3 и 6 делает один человек. Второй человек вслепую размечает случайные 20 пабликов, и мы считаем совпадение. Если совпадение ниже 80%, правила уточняются и разметка повторяется.

## 4. Выгрузка

### 4.1 Уровень паблика (`zamery/z20-publics.csv`, идёт в git)

`platform, sample (А/Б), type, id, url, name, city, members, posts_30d, median_views_30d, reach_rate (медианные просмотры / подписчики), median_er (лайки + комментарии + репосты) / просмотры, ad_share_90d, has_doctor_author (да/нет), collected_at`

### 4.2 Уровень поста (сырьё, **в git не идёт**)

Окно — 90 дней до даты сбора, не больше 300 постов на паблик. Только посты самого паблика: в ВК `filter=owner`, в Telegram посты канала.

`platform, community_id, post_id, date, text (первые 1 000 знаков), views, likes, comments_count, reposts, reactions, is_ad, has_video, has_photo, is_repost`

Из постов **не берём**: авторов, подписи вида «от подписчицы Марии», комментарии и их авторов, списки участников.

Сырьё лежит в `dlya-mam/_raw/` (папка в `.gitignore`) и удаляется через 90 дней после сбора. Причина — в постах мамских пабликов часто есть анонимные истории про здоровье конкретных детей. В модели такие тексты отправляются только после очистки: удаляются имена, `@`-упоминания, телефоны и ссылки.

### 4.3 Признак рекламы

Пост считается рекламным, если выполнено любое из условий: `marked_as_ads = 1` (ВК), в тексте есть `erid` (маркировка рекламы по закону с 2022 года), или есть «Реклама.» / «#реклама» в начале или конце текста.

### 4.4 Цена рекламы (П3)

Позже, отдельным шагом, после решения по П1. Администраторам 5 местных пабликов с наибольшим охватом отправляется **один стандартный запрос** прайса на пост и сторис. Текст запроса согласуется с владельцем. Ответы вносим в `zamery/z21-ad-prices.csv`. Контакты администраторов в git не попадают.

## 5. Классификация тем постов

Скрипт `scripts/publics/classify_posts.py` ставит посту одну или несколько меток по словарю:

| метка | группа | основа словаря |
|---|---|---|
| `night:*` (температура, дыхание, грудь, рвота, сыпь, ухо, живот) | ночь | 7 экранов v2 |
| `planned:*` (гв, прикорм, сон, прививки, атопия, смеси, зубы, развитие) | плановое | кластеры форума с наибольшим числом тем |
| `commerce` | реклама, розыгрыш, продам или куплю, скидка | исключается из сравнения тем |
| `other` | ни одна метка не подошла | — |

Проверка классификатора — так же, как З01. Человек вслепую размечает 100 случайных постов, и для каждой группы считается точность. Если точность группы ниже 70%, словарь правится и проверка повторяется. Сравнивать темы на непроверенном словаре нельзя.

## 6. Анализ и пороги решений (записаны до сбора)

| № | гипотеза | метрика | порог | решение |
|---|---|---|---|---|
| П1 | Местные паблики — заметный канал | сумма медианных просмотров поста у топ-10 местных пабликов (ВК и Telegram вместе) | < 15 тыс. — слабый; 15–50 тыс. — канал для партнёрства; > 50 тыс. — сильный | при «слабом» ставка на QR из клиник, паблики не первые. Обоснование: в НСО около 75 тыс. детей до 3 лет, 15 тыс. просмотров ≈ 20% мам (`ДОПУЩЕНИЕ`: одна мама на ребёнка, без пересечения аудиторий) |
| П2 | «Форумные» темы вовлекают сильнее ночных | медиана ER постов `planned` против `night` внутри одних и тех же пабликов, с бутстрэп-интервалом 95% | отношение ≥ 1,3 и интервал не пересекает 1 — подтверждено; ≤ 1,0 — отклонено; между — не решено | при «отклонено» паблик строится вокруг ночных тем со ссылкой на экраны, и курс через паблик продаётся хуже (Д14 пересматривается) |
| П3 | Паблики уже живут на рекламе | доля рекламных постов за 90 дней, медиана по выборке А | > 30% — рынок рекламы есть, партнёрство платное, нужен прайс | цена поста идёт в CAC канала «сообщества» в `03` |
| П4 | Есть местный врачебный конкурент | число живых местных пабликов, которые ведёт врач, с ≥ 5 тыс. подписчиков | ≥ 3 — конкурент есть | при «есть» уникальность берём не «врач отвечает», а «подпись НГУ + QR + Исход» |

Сравнение П2 делается **внутри пабликов**: отношение ER по темам считается в каждом паблике, потом берётся медиана. Иначе крупный паблик с одной темой исказит итог. Ноябрь — сезон ОРВИ, поэтому ночных постов может быть больше обычного. Это указывается в отчёте.

## 7. Правовые и этические рамки (без этого сбор не начинаем)

1. **Персональные данные (152-ФЗ).** Собираем только публичные метрики пабликов и тексты постов от имени паблика. Не собираем участников, комментаторов, авторов предложенных постов, сообщения в чатах.
2. **Здоровье детей — особая категория данных.** Сырьё не в git, хранится 90 дней, в модели идёт только после очистки (раздел 4.2).
3. **Правила площадок.** Работаем через официальные API и с их лимитами: ВК — не больше 3 запросов в секунду, Telegram — обычный клиент с паузами. Закрытые группы не вступаем, обход ограничений не используем.
4. **Секреты.** Токен ВК и `api_id/api_hash` Telegram передаются только через переменные окружения (`VK_TOKEN`, `TG_API_ID`, `TG_API_HASH`). В git, промптах и логах их нет. Файл сессии Telegram (`*.session`) — в `.gitignore`.
5. **Никакого участия.** Во время исследования не пишем в паблики, не ставим лайки и не продвигаем свой продукт. Контакт с администраторами — только стандартный запрос прайса (4.4), после согласования с владельцем.
6. **Тексты постов не публикуем и не цитируем** в материалах продукта. Это данные исследования, а не контент.

## 9. Команды

```bash
pip install telethon            # только для Telegram
export VK_TOKEN=...             # не коммитить
export TG_API_ID=... TG_API_HASH=...

python3 dlya-mam/scripts/publics/vk_collect.py search   # поиск по словам из этого файла → _raw/vk_found.csv
python3 dlya-mam/scripts/publics/vk_collect.py posts --ids _raw/vk_included.txt   # посты за 90 дней → _raw/vk_posts.csv
python3 dlya-mam/scripts/publics/tg_collect.py search
python3 dlya-mam/scripts/publics/tg_collect.py posts --usernames _raw/tg_included.txt

```

Список `*_included.txt` составляет человек после фильтра 3.4, а не скрипт.
