# Сайт Proba — этап 1 (каркас без дизайна)

Статус: **реализовано и проверено тестами локально**. Дизайн (этап «UX/UI») — editorial tech, см. раздел «Дизайн». Не развёрнуто на домен, интеграции Telegram и оплаты не подключены: в конфигурации пустые ссылки, токена нет.

Задание: [`docs/site/TZ_DEV.md`](../docs/site/TZ_DEV.md). Карта сайта: [`docs/site/SITEMAP.md`](../docs/site/SITEMAP.md). Решения: D-036 в [`docs/DECISIONS.md`](../docs/DECISIONS.md).

## Запуск

Нужен Node.js 20+.

```bash
cd site && npm install
```

```bash
npm run build          # продакшн-сборка в dist/: только одобренные медицинские материалы
```

```bash
npm run build:preview  # предпросмотр: черновики с плашкой «Черновик», всё noindex
```

```bash
npm run preview        # открыть собранный сайт: http://localhost:4321
```

```bash
npm run forms          # сервер приёма форм: http://127.0.0.1:8787
```

```bash
npm test               # все тесты (юнит + сборки на синтетических фикстурах)
```

`npm run dev` — режим разработки с перезагрузкой.

## Правила публикации (проверяются при сборке)

1. `medical: true` и `review.status ≠ approved` (или истёк `review.expires_at`) → материала нет в продакшн-сборке, нет в sitemap, на него нет ссылок.
2. У одобренного материала `review.content_sha256` должен совпасть с хешем текущего контента. Иначе сборка падает: `Материал «…»: текст изменён после рецензии … Нужна новая рецензия этой версии.`
3. В хеш входят заголовок, анонс (summary), текст, источники (включая ссылки и «на ком»), раскрытие и данные спонсорства. Правка любого из них отменяет одобрение.
4. Спонсорский материал: обязательно название рекламодателя (на странице — плашка «Реклама»), раскрытие не может быть «Независимый материал», в разделе pro запрещены `kind` razbor, ne-akne, pamyatka.
5. `pro_only` → `noindex`, нет в sitemap, текст скрыт до подтверждения на `/pro-dostup/` (отметка в localStorage; это не защита и не авторизация).
6. Спикер без `consent: true` и человек без `consent_public: true` по имени не выводятся.

## Как добавить материал

1. Создайте файл, например `src/content/materials/pro/pamyatki/guby.md` (папки внутри `materials/` — для удобства, URL строится из полей):

```yaml
---
title: "Памятка пациенту: губы после увеличения"
slug: guby
section: pro            # pro | dlya-vseh
kind: pamyatka          # hub | razbor | ne-akne | pamyatka | article
# hub: posle-procedur   # обязательно для section: dlya-vseh
summary: "До 200 символов: анонс и meta description."
medical: true
pro_only: false         # true — материал о лекарствах, только для специалистов
review:
  status: draft         # draft | in_review | approved
sources:
  - title: "Название работы"
    url: https://…
    year: 2024
    type: обзор         # обзор, РКИ, когортное…
    on_whom: люди       # люди | животные | клетки
disclosure: Независимый материал
updated_at: 2026-11-06
changelog: []
---
Текст в Markdown.
```

URL: `pro` + `pamyatka` → `/pro/pamyatki/<slug>/`, `razbor` → `/pro/razbory/<slug>/`, `ne-akne` → `/pro/ne-akne/<slug>/`, `article` → `/pro/materialy/<slug>/`; `dlya-vseh` → `/dlya-vseh/<hub>/<slug>/`. `kind: hub` — вводный текст хаба по адресу `/<section>/<slug>/`.

2. Проверьте в предпросмотре: `npm run build:preview && npm run preview`.

## Как внести рецензию

Решение о рецензии принимает **человек-врач**. Сайт только сверяет запись с текстом.

1. Рецензент читает финальную версию в предпросмотре.
2. Посчитайте хеш именно этой версии:

```bash
npm run hash -- src/content/materials/pro/pamyatki/guby.md
```

3. Заполните блок `review` по решению рецензента:

```yaml
review:
  reviewer_name: "Имя Фамилия"     # только с согласия на раскрытие имени
  reviewer_title: "врач-дерматовенеролог"
  reviewed_at: 2026-11-10
  expires_at: 2027-11-10           # необязательно: после даты материал снимается
  version: 1
  content_sha256: "<хеш из шага 2>"
  status: approved
```

4. Любая правка текста после этого — сборка упадёт, пока не будет новой рецензии (новый хеш, `version + 1`, запись в `changelog`).

## Формы

Три формы: лист ожидания вебинара, лист ожидания клуба, заявка партнёра. HTML-формы отправляются на `forms_endpoint` из конфигурации.

- Без отметки согласия браузер форму не отправит, а сервер вернёт ошибку `consent_required`.
- Скрытое поле-ловушка `website`: заявка с ним отбрасывается, боту отвечаем как при успехе.
- Ограничение частоты: 5 заявок с одного IP за 10 минут.
- Заявка сначала записывается в `var/forms/submissions.jsonl`, потом отправляется уведомление. Если уведомление не ушло, оно стоит в `notify_queue.jsonl` и повторяется при старте и раз в 5 минут.
- В логах только тип, номер заявки и код причины. Персональные данные в логи не пишутся. Уведомление в Telegram тоже без персональных данных: тип и номер заявки.
- Без `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` уведомления выключены.

## Дизайн

Стиль editorial tech по заданию владельца (6 ноября 2026): фон `#f7f6f2`, текст `#1c1c1c`, акцент `#3d7068`, линии 1px `#e5e4de`, фоновая сетка 40px с радиальной маской и направляющими на 25/50/75%, анимации `cubic-bezier(0.16, 1, 0.3, 1)` 700–1000 мс, скругления не больше 2px, без теней-разделителей и градиентов.

- `src/styles/global.css` — токены и все стили; `src/styles/fonts.css` — шрифты.
- `src/scripts/ui.js` — шапка при прокрутке, мобильное меню, появление секций, «чтение» текста по словам, шаги, вкладки. Без JS весь контент виден; `prefers-reduced-motion` отключает анимации.
- Шрифты лежат на нашем сервере (@fontsource), без Google Fonts. Playfair Display — заголовки (самое тонкое начертание с кириллицей — 400). Space Grotesk и Space Mono не содержат кириллицы, поэтому русские буквы рисуют Golos Text и IBM Plex Mono, латиница и цифры — Space.
- Картинка в карточке «Источник → рецензия → версия» — схематичный SVG, а не фото: стоковых изображений в проект не берём.
- Цифры спроса на главной — Яндекс Вордстат из `docs/site/SITEMAP.md`, не выдуманы.

## Ограничения этапа 1
- Медицинских текстов нет: досье не готовы, все ⚕-материалы — `draft` с `[ДОСЬЕ]`. Поэтому в продакшне хабы показывают «Раздел готовится».
- Одобрение в YAML — это запись в git, а не аутентифицированное решение. Связь с рецензией Proba Intelligence Engine (`schemas/review.schema.json`, два независимых решения) — следующий этап.
- Правовые тексты — шаблоны с полями `[…]` и `TODO(юрист)`.
- Ограничение частоты хранится в памяти процесса: для нескольких экземпляров сервера нужен общий счётчик.
- Хранилище заявок — файл JSONL. Шифрование, сроки хранения и резервные копии — решение владельца по хостингу в РФ (Q-03).
- Подтверждение «я специалист» — не защита: текст есть в HTML.
- Упоминание НГУ выключено (`partners.ngu_confirmed: false`) до договора или письма.
