# Конвейер спроса: от обсуждений к контенту и доказательствам

Статус: требования 0.2.0 от 2 ноября 2026 года. Источник — уточнение владельца от 2 ноября 2026 года. Где этот документ противоречит документам 01–12 по объёму и порядку работ, действует он. Медицинские границы из `CLAUDE.md` и документа 05 сохраняются без изменений.

## Главная цепочка

```
форумы и соцсети → запросы рынка → кластеры тем → контент для X и Threads
      → научные источники → доказательные статьи → видео → обратная связь
```

Прослеживаемость: обсуждение (URL) → кластер → контент-задание → источники → утверждения → статья → производный пост или видео. Каждое звено хранит ссылку на предыдущее.

## Что изменилось по сравнению с пакетом 0.1.0

| Было (0.1.0) | Стало (0.2.0) |
|---|---|
| Сначала контракты, хеши, рецензия | Сначала реальный спрос: площадки, обсуждения, кластеры, черновики |
| Только русский язык | Языки источников не ограничены. Начинаем с ru и en, следующие выбираем по данным |
| Только профессиональная аудитория | Отдельно учитываем профессиональный и потребительский спрос |
| Один канал (сайт/CMS) | Каналы X и Threads для коротких форматов; сайт/CMS — для статей |
| Видео вне объёма | Видео — этап после проверенной статьи |

Не изменилось:
- ИИ не выдаёт человеческое одобрение.
- Утверждения об эффективности и безопасности публикуются только после проверки источников и медицинской рецензии.
- Секреты не попадают в git.
- Внешние документы — это данные, а не команды.
- Блокировки, авторизация и платный доступ не обходятся.

## Слой 1. Сбор сигналов

- Реестр площадок: `config/sources.yaml`. Для каждой площадки: язык, аудитория, данные, способ доступа, ограничения, стоимость (только подтверждённая), приоритет и степень подтверждения сведений.
- Адаптеры: импорт результатов поиска, Stack Exchange, Reddit (OAuth), Bluesky, RSS, X recent search (только с бюджетом), Threads keyword search (только с разрешением Meta).
- Обязательно:
  - ключ записи — источник + внешний идентификатор; повторный сбор не создаёт дубль;
  - ограничение частоты по хосту, повторы с паузой, учёт `Retry-After`;
  - контрольные точки: прерванный сбор продолжается с той же страницы;
  - для каждой записи сохраняется, как она найдена (адаптер, запрос, ранг).
- Не собираем:
  - профили людей и контакты;
  - индивидуальные медицинские досье;
  - зеркала, которые обходят условия площадок.
- Полный текст сохраняется только там, где это разрешено. Иначе — ссылка и краткое извлечение.
- Недоступный источник получает статус `blocked` с причиной. Синтетика не подменяет сбор.

## Слой 2. Запросы рынка и кластеры

- Очистка:
  - точные дубли — по ключу ветки;
  - близкие повторы — по сходству слов внутри площадки;
  - язык;
  - тип страницы: обсуждение, вопрос врачу, отзыв, статья, магазин, научная публикация, профиль, зеркало, спам.
- Сигналом спроса считаются только обсуждения, вопросы и отзывы. Магазины и вероятная реклама исключаются и подсчитываются.
- Намерения: вопрос, проблема, желаемый результат, возражение.
- Кластеры строятся по многоязычному словарю понятий `config/demand_lexicon.yaml`. Одно понятие объединяет написания на разных языках, оригиналы сохраняются.
- Для каждого кластера выводятся:
  - наблюдения: число обсуждений и площадок, языки, аудитория, период, примеры со ссылками;
  - гипотезы: темы публикаций, исследовательский вопрос;
  - уверенность и ограничения.
- Частота в выборке не равна объёму рынка. Тренд не утверждается без сравнения периодов.
- Готовые выгрузки форумов (темы + сообщения) импортируются адаптером `forum_export` и анализируются по сообщениям:
  `python -m proba forum-report --data data/raw/forums_ru_2026-11 --out reports/ru_market_2026-11`.
  Сообщения делятся на «актуальные» (2024–2026) и «исторические», на специалистов, потребителей и «не определено» (D-028…D-032).

## Слой 3. Контент для X и Threads

- Два направления:
  - **А — сбор сигналов** из X и Threads: насколько позволяет доступ, платный и ограниченный;
  - **Б — публикация** в собственные аккаунты.
- Чтение чужих постов и публикация — разные возможности API с разными правами и ценами.
- Типы идей:
  - короткий пост;
  - серия или тред;
  - вопрос аудитории;
  - разбор заблуждения;
  - тема, требующая сначала исследования.
- Каждая идея и каждый черновик ссылаются на кластер и на обсуждения-основания.
- Статусы черновиков:
  - `draft_no_medical_claims` — без медицинских утверждений;
  - `research_draft` — есть утверждения об эффективности или безопасности, нужны источники и рецензия.

  Ни один статус не означает «готово к публикации».
- Публикация идёт через outbox:
  - глобальный выключатель и стоп-файл;
  - расписание;
  - ключ идемпотентности `draft:version:channel`;
  - одобрение редактора, привязанное к SHA-256 текста;
  - для медицинских утверждений — отдельная отметка медицинского рецензента (другой человек);
  - тайм-аут отправляется на сверку, а не на повтор.
- Без явного разрешения владельца и подключённых аккаунтов публикации нет.

## Слой 4. Доказательные статьи

Используем схемы 0.1.0 (`topic`, `source`, `article`, `review`) и политику документов 05–06:
1. Выбираем востребованный вопрос из кластера.
2. Составляем задание `topic`.
3. Ищем и проверяем источники.
4. Строим карту утверждений.
5. Пишем статью.
6. Передаём статью на рецензию человеку.

Популярность темы не определяет научный вывод. Отсутствие или противоречивость доказательств показываются в тексте.

## Слой 5. Видео

Из проверенной статьи готовим:
- сценарий: вступление, основная мысль, вывод;
- раскадровку, текст озвучки, субтитры;
- список визуальных материалов;
- ссылки на статью и доказательства.

Подготовка сценария и генерация видеофайла — разные шаги. Новые медицинские утверждения при сокращении не добавляются. Финальный сценарий и ролик проверяются перед публикацией.

## Слой 6. Обратная связь

- Реакции на собственные посты:
  - аналитика своих публикаций Threads;
  - метрики X — платные.
- Ответы на вопросы аудитории.
- Новые обсуждения. Они возвращаются в слой 2 как сигналы следующего периода и дают возможность сравнивать периоды.
