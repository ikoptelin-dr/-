# ТЗ: сайт Proba, этап 1 (структура и функциональность без дизайна)

Версия 0.1 · 5 ноября 2026 · для Claude-разработчика.

UI и визуальный дизайн делает владелец отдельно. Задача этого этапа — **рабочий каркас без стилей**: страницы, контентная модель, формы, SEO, правовые блоки, тесты. Вёрстка — семантический HTML без декоративного CSS, чтобы дизайн лёг поверх.

## 1. Цель

Сайт — дом профессионалов Proba Pro и научная база. Он должен:
1. показывать материалы по карте сайта (`docs/site/SITEMAP.md`);
2. собирать подписчиков в Telegram (бот) и заявки (партнёры, вебинары);
3. принимать предзапись на вебинар;
4. доказывать независимость: рецензия, версия, источники, правила рекламы — видимы у каждого материала.

## 2. Стек (предложение, можно обосновать другой)

- **Статический генератор Astro** (или аналог): быстрые страницы, хорошее SEO, контент в Markdown в git.
- **Контент:** Markdown/MDX в репозитории (`site/src/content/`), коллекции с проверкой схемы (zod).
- **Формы:** одна серверная функция или небольшой бэкенд, который сохраняет заявки и отправляет уведомление в Telegram. Хостинг и хранение данных форм — в РФ (конфигурируемо). Секреты — только через переменные окружения.
- **Без внешних счётчиков и трекеров по умолчанию.** Аналитика — опционально, после согласования (152-ФЗ, cookie).
- **Платёж за вебинар** — на этапе 1 кнопка ведёт на внешнюю ссылку оплаты из конфигурации; интеграция с платёжным сервисом — этап 2.

Код — в новой папке `site/` этого репозитория. Python-конвейер `src/proba/` не трогать.

## 3. Контентная модель

Все медицинские материалы опираются на существующие контракты `schemas/article.schema.json` и `schemas/review.schema.json` (версия 0.1.0). Расширения — отдельные поля сайта, без изменения схем без записи в `docs/DECISIONS.md`.

### Коллекция `materials` (разборы, хабы, карточки «не акне», памятки, статьи «для всех»)
| Поле | Тип | Обязательно | Примечание |
|---|---|---|---|
| title | строка | да | заголовок словами аудитории |
| slug | строка | да | |
| section | enum: pro, dlya-vseh | да | |
| kind | enum: hub, razbor, ne-akne, pamyatka, article | да | |
| summary | строка ≤ 200 | да | для анонса и meta description |
| medical | bool | да | true → публикация только при `review.status = approved` |
| pro_only | bool | нет | материалы о лекарствах: показывать после подтверждения «я специалист» |
| review | объект | если medical | reviewer_name, reviewer_title, reviewed_at, version, content_sha256, status: draft/in_review/approved |
| sources | массив | если medical | title, url, year, type (обзор, РКИ, …), on_whom (люди/животные/клетки) |
| disclosure | строка | да | «Независимый материал» или текст раскрытия |
| sponsored | объект/null | нет | sponsor, marking_erid (позже) — только для раздела рекламы |
| updated_at | дата | да | |
| changelog | массив | нет | что изменено и когда |

**Правила сборки (проверка в тестах):**
- материал с `medical: true` и `review.status ≠ approved` **не попадает в сборку для продакшна** (в режиме предпросмотра показывается с плашкой «Черновик»);
- `content_sha256` в рецензии должен совпадать с хешем текущего текста; иначе сборка падает с понятной ошибкой «текст изменён после рецензии»;
- у `sponsored` материала обязательна плашка «Реклама» и название рекламодателя; такой материал не может иметь `section = pro` + `kind ∈ {razbor, ne-akne, pamyatka}`.

### Коллекция `webinars`
title, slug, audience, program (список), speaker (name, title, consent: bool), date (может быть пустой), duration, price, payment_url, status (presale/scheduled/done/waitlist), materials_after (список).
Спикер без `consent: true` выводится как «спикер будет объявлен».

### Коллекция `people` (редакция и эксперты)
name, role, bio, consent_public: bool. Без согласия — не выводится.

## 4. Страницы и шаблоны

Реализовать все страницы **MVP** из `docs/site/SITEMAP.md`. Тексты — из `docs/site/CONTENT_DRAFTS.md` как стартовые файлы контента.

Шаблоны:
1. Главная.
2. Хаб раздела (список материалов по kind/тегу).
3. Материал (заголовок, summary, текст, блок «Проверено», источники с пометкой «на ком», раскрытие, оговорка, changelog).
4. Вебинар (программа, спикер, дата/статус, кнопки «Записаться» и «Лист ожидания»).
5. Простая страница (о проекте, политика и т. п.).
6. 404.

Сквозное: шапка, подвал, блок «Получить в Telegram» (ссылка на бот с параметром материала, например `?start=pamyatka_guby`).

## 5. Формы

| Форма | Поля | Куда |
|---|---|---|
| Лист ожидания вебинара | имя, email или Telegram, роль (косметолог/врач/другое), город, согласие | хранилище + уведомление в Telegram |
| Лист ожидания клуба | то же | то же |
| Заявка партнёра | имя, организация, тип (клиника/учебный центр/бренд), город, сообщение, согласие | то же |

Требования: обязательный чекбокс согласия со ссылкой на `/soglasie-na-obrabotku/`; защита от спама (honeypot + ограничение частоты); никаких персональных данных в логах; ошибки сохраняются и не теряют заявку.

## 6. Доступ «я специалист»

Для `pro_only` материалов — страница-подтверждение «Я медицинский или косметологический специалист» (чекбокс, запоминается в localStorage/cookie). Это не авторизация и не защита, а соблюдение правил подачи информации о лекарствах специалистам; юрист уточнит формулировку.

## 7. SEO

- уникальные `title` и `description` из полей материала;
- `sitemap.xml` и `robots.txt` (черновики и pro_only — `noindex`);
- разметка schema.org: `MedicalWebPage`/`Article` с `reviewedBy`, `lastReviewed`, `citation`;
- человеко-понятные URL по карте сайта;
- Open Graph для превью в Telegram.

## 8. Правовые и служебные страницы

Политика конфиденциальности, согласие на обработку ПД, медицинская оговорка, «Реклама и независимость» — по черновикам. Отметить в коде TODO «финальный текст — юрист».

## 9. Конфигурация

Один файл конфигурации (без секретов): название, домен, ссылки на Telegram-каналы и бот, URL оплаты, адрес приёма форм. Секреты (токен бота уведомлений) — переменные окружения, пример в `.env.example`.

## 10. Критерии готовности этапа 1

1. Собирается одной командой, запускается локально.
2. Все MVP-страницы открываются, навигация работает, 404 есть.
3. Тесты:
   - медицинский материал без `approved` не попадает в продакшн-сборку;
   - несовпадение хеша рецензии → понятная ошибка сборки;
   - спонсорский материал без плашки → ошибка;
   - спикер без согласия не выводится по имени;
   - форма без согласия не отправляется; honeypot отсекает бота;
   - sitemap не содержит черновиков и pro_only.
4. Без декоративного CSS и сторонних трекеров.
5. README в `site/`: как запустить, где контент, как добавить материал и рецензию.
6. Коммиты в ветку `claude/quirky-hypatia-yjx091`.

## 11. Не делать на этапе 1

- дизайн и UI-кит;
- личный кабинет и авторизацию клуба;
- интеграцию платёжного сервиса (только внешняя ссылка);
- реальную публикацию на домен;
- выдумывать имена экспертов, медицинские тексты, источники.
