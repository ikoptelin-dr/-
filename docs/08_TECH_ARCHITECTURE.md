# Техническая архитектура

Статус: проект требований 0.1.0; функциональность предстоит реализовать.


Предлагаемая основа, ещё не реализована: модульный монолит Python, HTTP API, PostgreSQL и фоновый worker. Конкретные версии библиотек фиксируются при реализации после проверки совместимости. Для первого локального среза допустимы SQLite и ручной запуск worker; отличие от продакшн должно быть явно описано.

Модули: topics, sources, evidence, articles, reviews, publication, audit, usage. Адаптеры: поиск, LLM, CMS, аналитика. Интерфейсы отделяются от провайдера; тестовые адаптеры возвращают явно синтетические данные. Основной объект — версионный article; review хранится отдельно и не перезаписывается.

Проект API: POST /topics; POST /topics/{id}/runs; GET /articles/{id}; POST /articles/{id}/versions; POST /articles/{id}/reviews; POST /articles/{id}/publish; POST /articles/{id}/withdraw. Все изменения требуют авторизации, expected_version и записи аудита. Идемпотентность внешней публикации обязательна. Эти маршруты сейчас не существуют.

Worker получает только идентификаторы задач, проверяет состояние в БД и берёт ограниченный lease. Транзакция сохраняет состояние и outbox-событие; повторная доставка не создаёт второй выпуск. Независимый процесс публикации повторно проверяет допуск непосредственно перед вызовом CMS.

Хеш контента: SHA-256 от UTF-8 JSON объекта с полями title, body_markdown, claims, disclosures, specialty, language; ключи сортируются рекурсивно, разделители ',' и ':', ensure_ascii=false, allow_nan=false, переводы строк приводятся к LF, строки NFC. Порядок массивов сохраняется. Реализацию закрепить тестовыми векторами. status, timestamps и metrics в хеш не входят.

Безопасность: секреты вне репозитория; минимальные права адаптеров; HTTPS; редактирование логов; запрет произвольных URL и запросов во внутреннюю сеть в загрузчике; ограничения размера/типа файлов; резервные копии и тест восстановления. Источники не могут расширять права инструментов.

До продакшн: рабочая аутентификация, серверная RBAC, миграции, мониторинг, лимиты бюджета, restore-тест и согласованный срок хранения. Предлагаемое хранение: аудит 365 дней, временные извлечения 30 дней; владелец подтверждает после проверки требований своей юрисдикции. Медицинские персональные данные не входят в проектный набор данных.
